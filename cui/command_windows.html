Windowsコマンド

このページは、左側の項目リストから記事を選ぶと中央にコンテンツが切り替わります。右側にはページ内の目次があります。

概要

Windowsコマンドの活用方法を掲載しています。WindowsにはコマンドプロンプトとWindows PowerShellの2種類のシェルがあります。両方で使えるコマンド、片方しか使用できないコマンドがあります。そのため2つに大区分しています。両方で使えても片方にしか載せていませんので注意願います。

一つのウィンドウで複数のコマンドプロンプトやPowerShellをタブで切り替えて使用できるWindowsターミナルが便利です。Microsoft Storeで入手できます。

使い方

左の項目リストから選ぶ

左側のリンクをクリックすると、中央の記事が差し替わります。選択中の項目は緑色でハイライトされます。

右のアウトラインから移動する

右側には、現在表示中の記事の h2 / h3 が自動で一覧表示されます。クリックすると中央のコンテンツだけが滑らかにスクロールして該当見出しが表示されます。中央をスクロールすると、現在位置に合わせた見出しがアウトライン側でハイライトされます（Scrollspy 相当）。

ネットワークの調査

※ ネットワークの仮定条件： 端末のIP構成を次のように仮定します。お使いの環境に合わせて、読み替えてください。 IPv4アドレス：192.168.0.12 サブネットマスク：255.255.255.0 IPv4デフォルトゲートウェイ：192.168.0.1 ※デフォルトゲートウェイは端末の存在するネットワークの外部との接点。通常はルータのLAN側IPアドレスといわれます。 また、IPアドレスを192.168.0.150に固定したネットワーク上のプリンタが存在するとします。

１．端末のIP構成を確認する。

コマンドプロンプトで、ipconfig /allを実行します。実際のIP構成がわかったら、上記の仮定を修正してください。

すべてのネットワークアダプタのIP構成が表示されます。ネットワークアダプタの名称に注意して、設定値を確認してください。

２．ネットワーク上の各要素（ノード）との疎通や経路を確認する

pingで疎通を確認する。

ping 127.0.0.1（ループバック、端末のネットワークアダプタの正常性を確認する）

ping 192.168.0.1（デフォルトゲートウェイまでの疎通を確認する）

ping 192.168.0.150（ネットワーク上のプリンタとの疎通を確認する）

ping 8.8.8.8 （インターネット上にあるGoogleのDNSキャシュサーバまでの疎通を確認する）

ping www.google.com （googleのトップページを表示するWEBサーバまでの疎通を確認する）

※このようなドメイン名を含むホスト名に対してのpingは宛先ホストの死活状態だけでなく、DNSサービス（ドメイン名をグローバルIPアドレスに変換する）の利用可能可否も確認していることになる。
※外部からのICMP通信を拒否する設定しているルータやホスト等に対してpingした場合はパケットはロスします。また、送信4に対して受信2のように一部パケットロスする場合は、宛先や自身の端末を含め経路の機器等再起動で回復する場合があります。

tracertでターゲットまでの経路を確認する。

tracert 8.8.8.8 (GoogleのDNSサーバまでの経路を確認できます。)

tracert [IPアドレスまたはホスト名]という構文です。 ※Linuxその他のOSだと　tracerouteというスペルです。
pingと同じICMPというプロトコルを使います。ICMP応答が禁止されている区間は***というふうに表現されます。
tracert -d 名前解決をしない。グローバルIPのみを使う。オプションをつけない場合、経路上のホストがDNS逆引きで名前解決可能であればドメイン名表示となる。
※その他オプションを確認するには、tracertに限らないがWindowsの場合は、コマンドの後に半角スペースと/?をつける（例：tracert /?）。
コマンドの実行を停止したい場合は、Ctrl+CでOK。

pingやtracertは応答時間も表示されるので、ネットワークやインターネットのどの部分で遅延が発生しているか調べるときにも使います。

３．プロトコルの統計情報と現在のTCP/IPネットワーク接続状況を表示する。

netstat -a (端末の使用している通信ポートの一覧が表示されます。)

ポート番号とプロトコルおよび接続状況（確立や待機）を調査する。サーバなどの場合は、各サービスの稼働状況を確認できる。複数アプリケーションのポートの競合などを確認することもある。
接続の状況はESTABLISH（確立）やLISTENING（待機）、CLOSE-WAITやFIN-WAIT（切断へ移行中）、TIME-WAIT（タイムアウト待ち）などがある。

ネットワーク間の通信はパケットという単位で行われます。パケットには送り主と宛先の住所が必要です。
それがIPアドレスやドメイン名を含むホスト名です。それ以外にポート番号というものがあります。通信が確立しているポートが知りたい場合が あります。そのときに使うコマンドです。

ネットワークの設定

1. ネットワークのIP構成（IPアドレス、サブネットマスク、デフォルトゲートウェイ、DNSサーバーのアドレス）をコマンドで行う。

・ネットワークのIP構成を確認する。端末で使用するIPアドレスとサブネットマスク、デフォルトゲートウェイ（直近のルータのLAN側IPアドレスです）を確認する。DNSサーバは到達可能であれば、同じセグメント（サブネット）になくてもいいですし、インターネット上のDNSサーバでも構いません。

（例）A社はブロードバンドルータ（IP:192.168.0.1）でインターネット接続をしており、自分の端末（Windows10）にはIP:192.168.0.123を割り当てたい。クラスレスではなく、サブネットによるネットワークの分割は行っていない。したがってサブネットマスクは255.255.255.0、インターネット上の名前解決には上記ルータが代理応答可能であるが、8.8.8.8などインターネット上のDNSサーバを利用しても社内規定上問題ないと仮定しています。

Windowsのネットワーク接続の画面で見られる、イーサネットやWi-Fi（後に数字が付いていることもある）というのは、インターフェース名と呼ばれる。下記コマンドでは、「イーサネット」のことで、正確に入力する必要がある。

以下のコマンド（あるいはバッチファイル）はコマンドプロンプトを管理者として起動し、実行しないとエラーになるので注意。

設定→ネットワークとインターネット→アダプタのオプションの変更で「イーサネット」というインターフェース名でなければ、実在するインターフェース名に変えてください。

IPアドレスを固定

netsh interface ipv4 set address "イーサネット" static 192.168.0.123 255.255.255.0 192.168.0.1

netsh interface ipv4 set dns "イーサネット" static 192.168.0.1 primary

netsh interface ipv4 add dns "イーサネット" 8.8.8.8

LAN内のみのアクセス（IPアドレスは固定）

netsh interface ipv4 set address "イーサネット" static 192.168.0.123 255.255.255.0 none

netsh interface ipv4 set dns "イーサネット" static none primary

netsh interface ipv4 add dns "イーサネット" none

DHCP自動取得にリセット

netsh interface ipv4 set address "イーサネット" dhcp

netsh interface ipv4 set dns "イーサネット" dhcp

2. Wi-Fiの設定を保存・復元する

・Wi-Fiのプロファイルの確認

netsh wlan show profile メモ帳(notepad)などに内容をコピーしておく。

上記コマンドを実行すると、インターフェース名（ワイヤレスネットワーク接続とかWi-Fi、もしくはそれらに数字がついたもの）についての保存されたプロファイル（通常SSIDと同じ）が表示される。PSK（事前共有キー）などは表示されない。

・設定（接続するSSIDとそのパスワードや暗号化の方式など）をバックアップする。

※以降は必ず「管理者コマンドプロンプト」で実行します。上記で確認したプロファイルの設定ファイル（xml）をCフォルダ直下に保存するというのが、以下のコマンドの意味

netsh wlan export profile name=プロファイル名 folder=C:\

実際に検証すると、インターフェース名-プロファイル名.xmlというファイルが作成される。エラーが表示される場合は、余分なスペースが入っていないか等を確認します。

</sharedKey>

※事前共有キーを暗号化したものをWi-Fi接続時に入力してもつながりません。

プロファイルのバックアップ（保存時）にオプションで　key=clearを付加すると、 keyMaterialにはWi-Fi接続設定で直接入力できる事前共有キーが表示されます。

DNS情報の調査


nslookupコマンド

基本構文

nslookup -type=（レコード名）（ドメインまたはIPアドレス）（問い合わせ先のDNSサーバー名またはIPアドレスの指定）

・DNSサーバの種類：1.コンテンツサーバ（権威DNSサーバともいう。ホストのドメインを直接管轄する専用DNSサーバでホストの運用者が設置する）
2.キャッシュDNSサーバ（他のDNSサーバに再帰的なクエリを行い、その問い合わせ結果を一定期間保存し、次回同じドメイン名の問い合わせに迅速に応答する。 ）

・PCに設定されているDNSサーバ ：ネットワーク構成をDHCPで自動取得している場合、ブロードバンドルータのこと。接続しているISPのDNSサーバの代理として働く。
キャッシュDNSサーバは、ISPやGoogle、CloudFlareなどが設置・運用するパブリックDNSサーバ、法人や個人がLAN内に設置・運用するプライベートDNSサーバがある。
オープンリゾルバは攻撃に悪用されやすいので、プライベートDNSサーバやルータはLAN内のみから問い合わせ要求を受け付けるように設定しなければならない。

・レコード名はDNSサーバに記述された項目の区分といったもの。メールサーバに関するものはMXレコード、コンテンツサーバについてはNSレコード、送信者ドメイン認証に関する記述はTXTレコードに記載がある。

・問い合わせ先のDNSサーバー名またはIPアドレスの指定は省略可能だが、PCが使用しているDNSサーバがnslookupを拒否している場合は、1.1.1.1や8.8.8.8といったパブリックDNSサーバを指定する。

DMARC（DomainKeys Identified Mail）のレコードの確認

DMARCとは、受信側サーバでSPFおよびDKIMによる送信者ドメイン認証いずれにも失敗（DMARC=FAIL）した場合の取り扱いを示している。
下の例で行くと、～@sample.co.jpが差出人のメールがSPFとDKIMが失敗したときはp=noneに従い、何もしないが、sp=quarantineに従い、～@*.example.comというサブドメインからの詐称メールは隔離してくださいという意味。
rua=mailto:********-******@sample.co,jpは、そのような処理の集計レポートの宛先を示している。

nslookup -type=txt _dmarc.（メールドメイン名）

nslookup -type=txt _dmarc.sample.co.jp

権限のない回答： _dmarc.sample.co.jp text =
"v=DMARC1; p=none; sp=quarantine; rua=mailto:********-******@sample.co,jp"

p=quarantineもしくはrejectにすればいいと思うが、SPFは転送の場合もFAILかSOFTFAILになるので、DKIMが何かの間違いでFAILになる可能性を考慮していると思われる。
いずれにせよ、受信側サーバがDMARCまでは対応していないことが多い。その場合は処理が行われないのでnoneと同じ。

※dmarcの設定については、実際に運用してみて、誤って自社のメールが相手に届かないという事象がなければ、p=rejectにしているところが多い。

DNSサーバから得られる情報について

nslookupによってDNSサーバから得られる情報は、公開情報となるので、権威DNSサーバおよびDNSキャッシュサーバの管理者がどのような情報を表示させるかあるいは表示させないかを決めることができます。
したがって、問い合わせ先サーバを変更すれば、見れなかったのが見れるというのもありますので、工夫してみてください。nslookupでNXレコードを見れば、管轄の権威DNSサーバのホスト名がわかるので、それを問い合わせ先のサーバにすれば、詳しい内容が見れることがあります。

pingで表示されるDNS情報について

ping ドメイン名（ホスト名）を実行すると、PCが実際に宛先のIPアドレスの名前解決を行った結果が見れます。
ここでは実行結果は記載しませんが、pingで表示されたIPアドレスが、nslookupで出てこない場合。PCで設定されているDNSサーバがDNSキャッシュポイゾニングを受けている可能性があるとかないとか。
通常、outlook.comやgoogle.comは複数のIPアドレスを使ってホストされているので、pingの実行結果で表示されているIPアドレスがそのうちの一つであれば問題ない。あなたの運営するサイトがそれほど大規模でなければ、nslookupで複数のDNSサーバに問い合わせて、pingの結果と比較することは有益な気付きを与えることがある。

証明書管理および暗号化操作

Certutilコマンド

1.ハッシュ値の計算

ウィルスに感染した異なるファイル名の同一ファイルの存在を確認したり、ファイルが改ざんされていないことを示すために、ファイルとそのハッシュ値を合わせて開示する場合が多い。その検証時、ハッシュ値の計算が必要となる。
今回は「本日は晴天なり」という1文だけのテキストファイルを「テスト.txt」というファイル名で作成した。

certutil -hashfile ファイル名 アルゴリズム名

アルゴリズム名：MD2,MD4,MD5,SHA1,SHA256,SHA384,SHA512

certutil -hashfile "テスト.txt" SHA256

SHA256 ハッシュ (対象 テスト.txt):
f84671b48267afd0c7f512ba15ad30f1a4f01c1be769237f71b46ab239bcecb2
CertUtil: -hashfile コマンドは正常に完了しました。

「本日は曇天なり」と書き換えると
SHA256 ハッシュ (対象 テスト.txt):
7ba89110b0639e030bcdb68085393f1bd8fc7a4a5efd5493abf64c106f7a2b63
CertUtil: -hashfile コマンドは正常に完了しました。
大きくハッシュ値が書き換わった。

また、さらにファイル名を「本番.xlsx」と変更。
certutil -hashfile "本番.xlsx" SHA256
SHA256 ハッシュ (対象 本番.xlsx):
7ba89110b0639e030bcdb68085393f1bd8fc7a4a5efd5493abf64c106f7a2b63
CertUtil: -hashfile コマンドは正常に完了しました。 ハッシュ値は全く変化していない。
このようなハッシュ値の性質を利用することがセキュリティ上の問題解決に役立つことがある。

2.文字列をBASE64で変換

BASE64形式は、64進数で、すべてのデータをアルファベット(a~z, A~z)と数字(0~9)、一部の記号(+,/)の64文字で表すエンコード方式です。
ただ、データ長を揃えるためにパディングとして末尾に記号の=を使用するので、厳密にはbase64は、65文字の英数字から表現されます。したがって、メールの送受信で文字以外の画像や音声も使えるようになりました。
本来はバイナリデータを文字列でやり取りできるようにするためのものです。しかし、文字列も含めデータを整形できるので、暗号化の下処理、WEBサーバーへのリクエストなどメールの送受信以外にも広く使われています。

変換 certutil -encode 入力ファイル名　出力ファイル名


戻す certutil -decode 入力ファイル名　出力ファイル名

BASE64でエンコード/デコードする。

（例）'user:12345'をbase64でエンコードする。
echo user:12345 > source.txt && certutil -encode source.txt destination.txt && type destination.txt

（結果） destination.txtを表示すると
-----BEGIN CERTIFICATE-----
dXNlcjoxMjM0NSAgDQo=
-----END CERTIFICATE-----3EldEll6VTtMQHeK
（例）'dXNlcjoxMjM0NSAgDQo='をbase64でデコードする。
echo dXNlcjoxMjM0NSAgDQo= >from.txt && certutil -decode from.txt to.txt && type to.txt

（結果）user:12345
※Linux等、Unix系のBase64コマンドを使うと、エンコード後の値がdXNlcjoxMjM0NQo= 又は dXNlcjoxMjM0NQ== になったりするが、デコードするとuser:12345になるので、特に問題はないと思われる。

（この演習を行う際の注意）Windowsではファイルの上書きができず同じファイル名を使ったコマンドを２回打つとエラー（上書きできない）になります。繰り返し試すときはすでにあるファイルを削除してください。

3.証明書の操作（標準ユーザーと管理者での実行結果が異なる。）

通常はGUIで行う。コマンドを使う場合は、Microsoftの詳細情報 を確認してください。

（注意点）LocalMachine ストア操作には管理者権限が必要。
誤った証明書追加・削除は通信障害の原因になる。
PFX の秘密鍵は安全に管理する必要がある。

証明書の一覧表示

インターネットオプション>コンテンツ>証明書で、個人、ほかの人、中間証明機関、信頼されたルート証明機関、信頼された発行元、信頼されない発行元という区分で表示できる。certutilコマンドでもこの内容をCLIで表示できる。

certutil -store （ストア名）

代表的な証明書ストア名

  • My（個人）：クライアント証明書を格納します。
  • Root（信頼されたルート証明機関）：信頼するルートCA証明書を格納します。
  • CA（中間証明機関）：中間CA証明書を格納します。
  • TrustedPublisher（信頼された発行元）：信頼するコード署名などの発行元証明書を格納します。
  • Disallowed（信頼されていない証明書）：失効・ブロック対象の証明書を格納します。
  • AddressBook（その他のユーザー）：他のユーザーの証明書を格納します。
（例 1）信頼されたルート証明機関を確認
certutil -store Root
（例 2）ユーザーの自己証明書を表示
certutil -store -user My

証明書のインストール

certutil -addstore （ストア名） （証明書ファイル名）

（注意点）LocalMachine ストア操作には管理者権限が必要。
誤った証明書追加・削除は通信障害の原因になる。
PFX の秘密鍵は安全に管理する必要がある。

・プライベートCA証明書を信頼されたルート証明機関のストアにインポートする。
certutil -addstore root private_ca_cert.cer
・クライアント証明書（個人あるいは自己証明書）をユーザーの個人ストアにインポートする。
certutil -addstore -user my certfile.cer
・PFX（秘密鍵付き）証明書のインストール
certutil -importpfx My certfile.pfx
※端末認証で使う証明書はnoExportを指定して、端末の盗難や紛失に備える。

証明書のアンインストール

certutil -delstore （ストア名） （証明書のシリアル番号）

・使用しなくなったユーザーレベル（ローカルコンピュータではなく）で信頼されたルート証明機関でインストールされた証明書を確認
certutil -store -user Root
・シリアル番号を確認。ここではシリアル番号: 5c7e7c2xxxだったとする。実際はもっと長い。
・使用しなくなったプライベートCA証明書を削除する。
certutil -delstore -user Root 5c7e7c2xxx
・証明書の詳細が別ウィンドウで表示されるので、「はい」をクリック。
certutil -store -user Root
削除されたかを確認する。
